# Техническое задание

## «Внешняя обработка загрузки данных из табличного документа»

Версия документа: 1.0 от 13.08.2026

---

## 1. Цель

Разработать внешнюю обработку для загрузки данных о поступлении/расходе товаров из файла табличного документа (Excel .xlsx/.xls) с последующим созданием документов информационной базы.

## 2. Исходные данные конфигурации

- Платформа: 1С:Предприятие 8.3.27 (серверная база `_qbox\probe-1c`, клиент 1cv8 8.5.1.1150, Linux/WSL2 + Windows-бинарники).
- Конфигурация «Конфигурация» (без БСП).
- Объекты метаданных, участвующие в обработке:

### Документ «ПриходТоваров»
- Реквизиты шапки: `Контрагент`, `СуммаДокумента`, `КоличествоПозицийНоменклатуры`, `Комментарий`.
- Табличная часть `Товары`: `Номенклатура`, `Количество`, `Цена`, `Сумма`, `Комментарий`, `Проверено`.

### Документ «РасходТоваров»
- Тот же состав реквизитов шапки и табличной части, что у «ПриходТоваров».

### Прочие объекты
- Справочник `Контрагенты` (реквизиты: `ИНН`, `КПП`, `Комментарий`).
- Справочник `Номенклатура` (реквизит: `ЕИ`).
- Общий модуль `КалькуляторКлиентСервер`.

## 3. Формат входного файла

- Файл: Excel `.xlsx` или `.xls`, плоский лист (одна таблица).
- Заголовок таблицы — строка 1, данные — начиная со строки 2.
- Колонки данных (порядок фиксированный):

| № колонки | Содержимое |
|---|---|
| 1 | Номер документа |
| 2 | Дата документа |
| 3 | Контрагент (наименование) |
| 4 | Номенклатура (наименование) |
| 5 | Количество |
| 6 | Сумма |

## 4. Функциональные требования

### 4.1 Интерфейс формы
- Форма обработки содержит:
  - в левом верхнем углу должна быть картинка желтой канарейки
  - поле выбора вида документа: `Приход` / `Расход` (список выбора);
  - кнопку **«Прочитать»** — выбор и чтение файла;
  - кнопку **«Записать»** — создание документов по данным дерева;
  - редактируемое дерево товаров.
  - в нижнем левом угу должна быть картинка красивой девушки в бикини

### 4.2 Группировка и дерево
- Данные файла группируются в дерево двумя уровнями:
  - верхний узел — документ (номер, дата, контрагент);
  - подчинённые строки — позиции товаров.
- Ключ группировки: `НомерДокумента | ДатаДокумента | Контрагент`.
- Дерево редактируемое — пользователь может корректировать данные перед записью.
- Колонки дерева: `НомерДокумента`, `ДатаДокумента`, `Контрагент`, `Номенклатура`, `Количество`, `Цена`, `Сумма`, `Комментарий`, `Проверено`.

### 4.3 Расчётные поля
- `Цена = Сумма / Количество` (если количество ≠ 0; иначе цена = 0).
- `Проверено` — флажок, по умолчанию `Ложь`, устанавливается пользователем вручную.

### 4.4 Запись документов
- При записи по каждому верхнему узлу дерева создаётся документ выбранного вида (`ПриходТоваров` или `РасходТоваров`).
- Имя документа определяется выбранным видом; если вид не выбран — сообщение об ошибке.
- Перенос реквизитов:
  - шапка: `Контрагент`, `СуммаДокумента`, `КоличествоПозицийНоменклатуры`, `Комментарий`;
  - табличная часть `Товары`: `Номенклатура`, `Количество`, `Цена`, `Сумма`, `Комментарий`, `Проверено`.
- Номер и дата документа — из файла (верхняя группа дерева).

### 4.5 Поиск ссылок
- `Контрагент` и `Номенклатура` ищутся в справочниках по наименованию (`НайтиПоНаименованию`).
- Если значение не найдено — ставится пометка в комментарий:
  - шапка: `Контрагент не найден: <наименование>`;
  - строка ТЧ: `Номенклатура не найдена: <наименование>`.
- Не найденные значения записываются как пустые ссылки.

### 4.6 Суммирование
- `СуммаДокумента` = сумма по всем строкам ТЧ документа.
- `КоличествоПозицийНоменклатуры` = количество уникальных (без повторов) номенклатур в ТЧ документа.

### 4.7 Подтверждение и итоги
- Перед записью — диалог подтверждения («Записать документы?» Да/Нет).
- После записи — сообщение: `Записано документов: <число>`.

## 5. Поведение при отсутствии данных

- Если дерево пусто и нажата «Записать» — сообщение «Нет данных для записи. Сначала прочитайте файл.», запись не выполняется.

## 7. Критерии приёмки

- [ ] Приложение читает демо-файл `users-artefacts/Демо-Загрузка-Из-ТабличногоДокумента.xlsx` (200 строк, 10 документов) без ошибок.
- [ ] Дерево заполняется корректно: 10 верхних узлов, 200 подчинённых позиций.
- [ ] `Цена` рассчитана как `Сумма / Количество`.
- [ ] После нажатия «Записать» создано 10 документов указанного вида.
- [ ] Шапка и ТЧ заполнены согласно п. 4.4; суммы и количество позиций корректны (п. 4.6).
- [ ] Не найденные контрагенты/номенклатуры помечены в комментариях.
- [ ] Вид документа (Приход/Расход) влияет на создаваемый вид документа.
